# TodoApp-Web 開発記録

## 開発期間

2026年8月1日～2026年8月31日

Java / Spring Bootの学習を兼ねて、実際に日常で使用できるTodo管理Webアプリを目標に開発を開始しました。

単純なCRUDアプリで終わらせるのではなく、開発を進めながら必要な機能を検討し、実際にリリースをする想定で改善しています。


---

## 開発の流れ

### 1. Spring Boot版Todoアプリの開発開始

2026年7月、Javaの学習で作成したコンソール版Todoアプリを作成しました。
コンソール版を発展させる形で、Spring Bootを使用したWeb版Todoアプリ「TodoApp-Web」の開発を開始しました。

まずはTodoアプリとして必要な基本機能の実装からスタートしました。

主な基本機能：

- タスクの新規登録
- タスクの編集
- タスクの削除
- タスクの完了／未完了管理
- タスク検索
- タスクの絞り込み
- タスクの並び替え
- タスク件数表示

基本的なCRUDを完成させたあと、実際に使用することを想定した機能を段階的に追加していきました。


---

### 2. ユーザー認証・ユーザーごとのTodo管理

複数ユーザーで利用できるように、Spring Securityを使用した認証機能を実装しました。

実装内容：

- ユーザー新規登録
- ログイン
- ログアウト
- パスワードの暗号化
- ユーザー情報変更
- アカウント削除
- ユーザーごとのTodoデータ分離

特に、ログインしているユーザー以外のタスクを閲覧・編集・削除できないようにすることを重視しました。

URLを直接変更した場合なども想定し、他ユーザーのTaskに対する不正操作を防止しています。


---

### 3. Todo機能の拡張

基本的なTodo一覧だけではなく、「これから何をする必要があるのか」を確認しやすくするため、予定・締切を中心とした機能を追加しました。

主な追加機能：

- 予定日の設定
- 締切日の設定
- 時刻の設定
- 予定・締切の一覧表示
- 日付ごとのグループ表示
- 同じタスクへの時間・詳細追加
- 期限切れ表示
- 締切までの日数に応じた表示
- 日付を指定したタスク追加

予定と締切を単純なTask一覧とは別に整理して表示することで、Todoアプリを開いた際に今後の予定を把握しやすくしました。


---

### 4. UI・操作性の改善

Bootstrapを使用し、Todoアプリとして使いやすい画面構成へ改善しました。

PC版では、予定・締切とタスク一覧を分けた2カラム構成を採用しています。

また、以下のようなUI改善も行いました。

- Bootstrapを利用した画面デザイン
- タスクの状態をBadgeで表示
- 削除前の確認モーダル
- 成功・エラー通知モーダル
- ユーザーメニュー
- 予定・締切の視認性改善
- 操作ボタンの役割に応じた色分け

機能を追加するだけでなく、「初めて使う人でも操作方法が分かるか」を意識して改善しています。


---

### 5. ADMIN機能の実装

一般ユーザーとは別にADMINロールを用意し、管理者専用画面を実装しました。

主な管理者機能：

- ADMIN / USERの権限制御
- ユーザー一覧
- ユーザー詳細
- ユーザー削除
- 管理者追加
- ユーザー数の管理サマリー
- 管理者向け通知
- 管理画面とTodo画面の移動

一般ユーザーが管理者用URLへ直接アクセスした場合にも、管理機能を利用できないように制御しています。


---

### 6. 総合テストとセキュリティ確認

主要機能が揃った段階で、一度アプリ全体の総合テストを実施しました。

確認した主な項目：

- Todo CRUD
- ユーザーごとのデータ分離
- 他ユーザーTaskへの不正操作防止
- ADMIN権限制御
- ユーザー情報変更
- アカウント削除
- ログイン／ログアウト
- セッション
- 存在しないIDへのアクセス

テスト中に発見した問題についても修正しました。

例：

- 存在しないUser IDへのアクセス時に500エラー
  - 管理画面へ安全にリダイレクトするよう修正

- ログイン中のADMINが自分自身を削除できる
  - 自己削除を拒否し、警告を表示するよう修正

- 一般USERによるADMINページへのアクセス
  - 管理機能へのアクセスを拒否するよう修正


---

### 7. お問い合わせ機能の実装

ユーザーから管理者へ質問や意見を送信できる、お問い合わせ機能を実装しました。

当初は単純な送信機能として開始しましたが、開発を進めながら管理・返信・通知機能まで拡張しました。

#### ユーザー側

- 質問／意見の選択
- お問い合わせ送信
- 自分のお問い合わせ履歴
- 対応ステータス確認
- 管理者からの返信確認
- 未読返信のNEW表示
- 未読返信件数Badge
- ログイン時の返信到着モーダル

#### 管理者側

- 新規お問い合わせ通知
- お問い合わせ一覧
- 未対応／対応中／対応済み管理
- 管理者内部の回答・対応内容記録
- ユーザーへの返信
- 返信管理者・返信日時の記録
- 対応完了日時の記録
- 対応済みお問い合わせ履歴
- 対応済みから未対応／対応中への差し戻し

お問い合わせの状態を管理するだけでなく、ユーザーへの返信について未読／既読状態も管理しています。

管理者から返信が届いた場合にはTodo画面に未読件数を表示し、ログイン時にも返信到着モーダルを表示します。

実際にお問い合わせ履歴の詳細から返信を確認した時点で既読になるようにしています。


---

## 8月の開発を通して

開発開始時は基本的なTodo CRUDを中心としたアプリでしたが、約1か月の開発を通して、

- 認証・認可
- ユーザーごとのデータ管理
- 予定・締切管理
- 管理者機能
- 通知
- お問い合わせ
- 管理者からの返信
- 未読／既読管理
- 実ユーザーレビューをもとにしたUI改善

などを持つWebアプリへ発展しました。

開発では、一度にすべての機能を作るのではなく、

**仕様検討 → 実装 → 動作確認 → 既存機能の再テスト → 改善**

という流れを繰り返しています。

また、実際のユーザーにアプリを操作してもらうことを意識し、第三者視点で開発を行うことを意識することで、
開発者側では気づきにくい問題を発見し、仕様変更につなげる経験もできました。


---

## 開発方針

TodoApp-Webでは、機能数を増やすことだけを目的とせず、以下を重視して開発しています。

- 実際に使いやすいTodoアプリにする
- 既存機能を壊さないよう段階的に実装する
- 新機能追加後は既存機能もテストする
- ユーザーごとのデータ分離を維持する
- 認証・認可を崩さない
- 削除などの危険な操作には確認を入れる
- 実際のユーザーからのフィードバックを取り入れる
